# sdtmai

`sdtmai` is an independent R package for developing reviewable, AI-assisted SDTM workflows. It is separate from ClinicalAI and is not affiliated with that project.

Originally developed by Jannie Strydom as an independent project in 2026.

Current end-to-end support is focused on the SDTM Demographics (DM) domain.

## Capabilities

- Isolated project workspaces for inputs, metadata, mappings, code, and outputs
- Deterministic metadata generation from CSV and SAS7BDAT source datasets
- AI-assisted SDTM mapping informed by study documents and metadata
- Reusable mapping guidance supplied as YAML
- Programmer review and approval of generated mappings
- Validation of approved source-key identifiers against source metadata
- Deterministic source dataset reads generated by the package
- AI-assisted R transformation generation that produces `dm`
- Optional programmer-authored code instructions

## Installation

```r
remotes::install_github("jstrydom/sdtmai")
library(sdtmai)
```

## Configuration

Create the AI configuration in R. Keep credentials outside source code and expose them through an environment variable.

```r
ai_config <- sdtm_ai_config(
  model = "gpt-5.6",
  api_key_env = "SDTM_AI_API_KEY"
)
```

## Workflow

### 1. Create an isolated project

```r
project <- sdtm_project_create(
  root = "C:/ClinicalStudies/ABC-PHARM-01",
  in_dir = "C:/ClinicalStudies/ABC-PHARM-01/source"
)
```

The returned project object provides these paths:

```r
project$root
project$in_dir
project$metadata_dir
project$mapping_dir
project$code_dir
project$out_dir
```

### 2. Generate source metadata

```r
metadata_file <- file.path(project$metadata_dir, "meta_data.json")
sdtm_generate_metadata(project = project, output_file = metadata_file)
```

Metadata is generated deterministically by inspecting CSV and SAS7BDAT files in `project$in_dir`.

### 3. Generate a draft DM mapping

```r
guidance_file <- system.file(
  "mapping_library",
  "sdtm_mapping_guidance.yaml",
  package = "sdtmai"
)

draft_mapping <- sdtm_generate_mapping(
  domain = "DM",
  metadata = metadata_file,
  sdtmig = "reference/SDTMIG.xlsx",
  protocol = "study/Protocol.docx",
  acrf = "study/Annotated_CRF.docx",
  treatment_arms = "study/Treatment_Arms.xlsx",
  ai_config = ai_config,
  mapping_guidance = guidance_file,
  output_file = file.path(project$mapping_dir, "DM_mapping_review.csv")
)
```

The generated mapping is a draft for programmer review. Review it, correct it as needed, and explicitly approve the rows that should be used for code generation.

### 4. Validate the reviewed mapping

```r
validation <- sdtm_validate_mapping(
  mapping = file.path(project$mapping_dir, "DM_mapping_review.csv"),
  metadata = metadata_file,
  sdtmig = "reference/SDTMIG.xlsx",
  output_file = file.path(project$mapping_dir, "DM_mapping_validated.csv")
)
```

Validation checks the mapping structure and confirms that approved source-key identifiers refer to available source metadata.

### 5. Generate DM transformation code

```r
generated_code <- sdtm_generate_code(
  mapping = file.path(project$mapping_dir, "DM_mapping_validated.csv"),
  metadata = metadata_file,
  ai_config = ai_config,
  project = project,
  project_key = "project",
  subject_key = "SubjectId",
  site_key = "SiteNumber",
  visit_key = "Folder",
  code_instructions = "code_instructions.md",
  output_file = file.path(project$code_dir, "dm.R")
)
```

`code_instructions` is optional and can contain concise, project-specific instructions for the generated transformation code.

## Reusable mapping guidance

The package ships reusable guidance at:

```text
inst/mapping_library/sdtm_mapping_guidance.yaml
```

Access the installed file with:

```r
system.file(
  "mapping_library",
  "sdtm_mapping_guidance.yaml",
  package = "sdtmai"
)
```

The YAML is intended for reusable conventions and nontrivial mapping guidance. Direct source-to-target mappings normally do not belong there because current source metadata is the authoritative input for those mappings.

## Deterministic source reads

Source reads are not generated by AI. The package constructs `in_dir` and every approved source dataset read deterministically from `project$in_dir` and each dataset's `metadata$file_name`. It then supplies the resulting source object names to the AI, which generates only the R transformation block that produces `dm`. The deterministic read block and AI-assisted transformation block are combined when `dm.R` is written.

Generated mappings and code remain subject to programmer review and approval before use in a regulated workflow.
